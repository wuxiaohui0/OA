# 完整 OA 能力路线图

当前系统已覆盖请假、销假、额度、日历、组织人员、站内通知、智能助手、费用报销、出差、采购、加班与调休审批。要继续从“请假试点”扩展为完整 OA，建议按下面的顺序建设：

## 已落地

- 费用报销：员工新建草稿、提交审批、审批人批准/驳回、申请人撤回，全部写入独立审计流水。
- 出差申请：员工填写地点、事由、出发/返程时间、同行人、交通和住宿标准，提交直属审批人审批，支持批准、驳回、撤回和审计流水；审批通过后可作为差旅报销的业务依据。
- 采购申请：员工填写用途、预算、供应商、需求日期和多条采购明细，系统校验明细金额不超过预算，支持草稿、提交、批准、驳回、撤回和独立审计流水。
- 加班与调休：员工提交加班时段、事由和补偿方式；选择调休补偿的加班审批通过后按时长增加调休余额，选择加班费不增加余额。调休申请审批通过后扣减余额，支持草稿、提交、批准、驳回、撤回和审计流水。
- 审批数据分析：管理员查看总量、待办、通过率、平均处理时长、部门/假别分布、超时待办和 AI 升级风险，并导出明细 CSV。

## 下一阶段

1. 通用审批模板：由管理员配置表单字段、审批节点、条件分支、抄送人和 SLA，而不是为每个业务单独写页面。
2. 电子档案与合规：附件病毒扫描、敏感字段脱敏、电子签名、归档保留策略和审计导出。
3. 通知与集成：企业微信/钉钉、邮件、SSO/OIDC、考勤、财务和 ERP 接口。
4. 移动端与运营：移动端适配、离线草稿、批量审批、审批委托、仪表盘订阅和异常告警。

通用审批模板稳定后，再把费用报销、出差、采购和加班迁移到模板引擎，避免形成多个互不兼容的流程实现。
