# 智能助手：在对话中办事

侧栏“智能助手”和顶部助手按钮进入统一对话。申请详情中的“在对话中办理这条申请”会带入当前申请，随后可继续说需求。业务页面与聊天共用业务服务、账号权限、状态机、额度和审计记录。

## 可以办理的事项

| 事项 | 支持内容 |
| --- | --- |
| 请假 | 一次确认完成申请与提交、单独保存草稿、修改、退回后修改重提、撤回、删除、催办 |
| 审批 | 查询待办、查看详情与 AI 建议、人工确认批准/驳回/退回、交接审批 |
| 销假 | 全部或部分销假、撤回销假、批准/驳回销假、交接销假审批 |
| 出差 | 地点、事由、时间、同行人、交通与住宿标准；创建草稿、提交与撤回 |
| 采购 | 用途、预算、供应商、需求日期和多条采购明细；创建草稿、提交与撤回 |
| 加班与调休 | 加班时段、事由、补偿方式、调休日期及时长；创建草稿、提交与撤回 |
| 材料 | 选中申请后直接上传 PDF/PNG/JPG、下载材料、删除未提交草稿的材料 |
| 查询 | 我的申请、审批记录、余额流水、工作日历、通知、组织人员 |
| 台账与通知 | 下载本人/有权限员工的台账 CSV、全部通知标记已读 |
| HR 管理 | 日历设置与恢复默认、调整额度、员工入职/资料修改/停用、部门新增修改、岗位和权限角色新增 |

这些能力以项目已有业务模块为范围。出差、采购、加班与调休的审批和列表查询使用对应业务页面；对话中的审批、材料、余额和申请查询目前针对请假。多级审批、批量自动审批和通用审批模板尚未实现。密码重置、开通已有账号、自助改密仍使用原账号页面；入职初始密码通过确认卡片专用输入框提交。附件内容不由模型自动读取或核验。

## 使用示例

配置模型后可使用以下表达，日期换成实际未来日期：

1. “明天请假，原因是昨天没休息好，要休息” → 核对假别、日期、时长、原因和审批人 → 点击“确认请假并提交” → 进入领导审批待办。无需再说“提交这条”。
2. 如果需要先准备材料，可明确说“明天下午请病假，先存草稿，原因：需要就医检查” → 确认保存草稿 → 上传材料 → “提交这条” → 确认提交。
3. 审批人说“待我审批”，点击某条申请 → “查看详情” → “批准这条”或“退回补充，原因：请补充交接安排” → 核对确认。
4. 员工选择已批准申请 → “2026-10-12上午销假，原因：提前返岗” → 确认；主管从销假待办选中记录 → “批准销假，原因：确认返岗” → 确认返还。
5. “我的余额”“工作日历”“消息通知”“组织人员”。HR 可说“查询陈默的余额”。
6. “转交给周宁，原因：出差交接” → 核对新审批人 → 确认。

自然语言请求统一进入当前账号的 Agent Runtime，由 Agent 自主选择已绑定工具或技能。未配置模型或模型调用失败时不会使用关键词规则代替 Agent 办理；HR 管理和精细字段仍可展开对话底部“办理业务”，选择事项、填写字段、生成预览，然后确认，整个过程留在对话内。

模型异常时保留已生成的预览或查询卡片，尚无结果时提示重试或使用表单。表单与模型调用共用同一工具操作与人工确认机制。

“明天请假，家中有事”这样的常见表达由 Agent 直接生成待确认请假。未明确假别时按事假、未明确时段时按全天，在预览中展示供用户核对；可点击“修改信息”更正假别、时间、原因与交接安排。Agent 追问假别时仍提供年假、事假、病假选项，选择后沿用前文信息准备确认卡片。

## 确认、权限与恢复

- 普通查询立即返回卡片；业务工具调用在执行前暂停，模型没有替用户确认的工具。
- 申请请假、修改、审批和管理变更都先生成服务端预览。独立的人工确认区位于滚动聊天记录下方，按钮按操作显示“确认请假并提交”“确认修改”“确认批准”等；点击按钮或明确回复“确认执行”后生效，“好的”“谢谢”不会执行。入职密码必须使用专用输入框；材料上传由用户选择文件直接完成。
- 请假预览可点击“修改信息”后更新确认卡片，更新预览不会写入申请；修改期间不能确认旧内容，新卡片生成后旧卡片失效。“取消操作”不会执行业务变更。普通请假只确认一次，确认后工具完成创建与提交，最终批准仍由领导决定。只有明确要求暂存草稿时才走单独保存流程。
- 缺少信息时展示补充区，信息补齐并生成有效预览后才出现执行确认按钮，避免对不完整操作进行确认。
- 当前会话只保留一项待执行预览，准备新操作会取消旧预览。多个可能的申请需先选择，不自动批量处理；当前申请与确认卡片均显示业务对象。
- 待确认操作 30 分钟过期。权限、申请、余额、相关日历或组织数据变化后，旧预览会被拒绝，重新发起即可。确认时仍重新执行业务校验。
- 重复确认同一操作返回原回执，不重复创建、提交、扣减或返还。申请并提交工具将申请创建、提交事件和执行状态在同一事务中保存；校验失败不会留下草稿。模型辅助审核在事务外运行，重启后按持久化提交事件恢复结果和当前申请。
- 当前会话 ID 保存在本地浏览器，内容与操作存 SQLite。刷新或重启后可继续；“新对话”前需处理或取消待确认卡片。暂不提供历史会话列表。
- 查询卡片刷新时重新查询；当前申请展示最新状态。审批日志记录人工确认者，AI 仍提供辅助建议。
- 菜单、工作台、聊天快捷键和办理事项目录按当前账号权限展示；普通员工看不到审批或组织管理操作，后端在准备与确认时也会校验权限。员工的组织入口为只读通讯录。当前申请的提交、催办、审批及上传入口同时按本人关系和业务状态展示。

## 实现与验证

入口为 `/api/agent/messages`，操作预览为 `/api/agent/prepare`，确认/取消接口为 `/api/agent/actions/{id}/confirm|cancel`。工具和表单复用领域输入模型；后端维护操作目录，前端按字段生成表单。会话与操作分别存于 `assistant_conversations` 和 `assistant_actions`。

模型通过专用 `apply_leave` 工具申请并提交请假，通用 `prepare_oa_action` 支持出差、采购、加班和调休目录操作。工具调用先存为 `pending` 并返回确认卡；只有本人确认接口能继续执行业务服务。普通请假的操作链是 `apply_leave → pending → 用户确认 → 创建并提交 → 人工审批中`。其他业务先确认创建草稿，回执包含申请编号；随后可以要求提交审批，核对并确认提交卡片后进入人工审批。`create_leave` 保留用于明确暂存草稿的需求。

使用单 API 工作进程。会话按账号隔离，空闲 30 天后失效，聊天滚动保留 40–60 条消息，业务审计独立保留。过期会话尚未自动物理清除；扩大部署前需确定数据保留策略及跨进程锁。

自动化用例见 `apps/api/tests/test_assistant_workspace.py`，涵盖完整办理链、权限隔离、幂等、旧预览拒绝、长会话确认、重启恢复与模拟模型工具边界。测试使用独立数据库，不修改公司实际申请或额度。
