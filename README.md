# FlowMind 智能 OA 审批平台

一个前后端分离的企业内部智能审批系统，当前聚焦单部门请假试点。AI 辅助填写与检查，最终由人工审批。试点配置和验收流程见 [请假试点使用说明](docs/leave-pilot.md)。

当前实现：

- 人工填写请假表单并提交；
- 智能助手支持自然语言查询、准备操作、在聊天卡片中确认执行，复杂字段可通过聊天内表单填写；
- 员工一句话提出请假需求，核对后点击“确认请假并提交”，即可完成申请并送审；对话也支持修改、撤回和销假，审批人可查询待办并在对话卡片中逐笔确认审批；
- 代码状态机控制所有流程迁移；
- Deep Agents 生成结构化审核意见；
- 所有申请进入配置的请假审批人的人工待办，可批准、驳回、退回补充或转交；
- 支持修改重提、全额/部分销假、工作日历、额度台账、材料、站内通知与催办；
- 审批、驳回、Agent 审核和系统流转全程留痕。
- 申请人可以删除草稿或撤回并隐藏审批中的申请，审计记录不会物理删除。
- 系统管理员分配和管理 HR 账号；HR 维护组织层级、负责人，办理普通员工入职、调岗及账号停用；员工可查看自己的组织、直属领导与汇报链。
- 入职时账号、工号、组织关系、初始假期额度和审计记录在同一事务中保存。
- 职位和权限角色均可自定义；角色分别配置组织管理、账号管理、担任负责人、请假审批权限。
- 支持明确标记“无直属领导”，并单独指定请假审批人；提交后保留组织和审批人快照。
- 对话支持材料上传下载、台账查询导出、通知已读，以及按权限开放的日历、额度、组织和入职操作。

对话办事的支持范围、示例和确认机制见 [智能助手使用说明](docs/conversation-workspace.md)。

## 员工入职与组织关系

使用 HR 账号登录后，打开“组织与人员”：

1. 在组织架构中新增或编辑公司、部门、团队，指定组织负责人。
2. 选择所属组织，点击部门旁的“添加人员”，填写姓名、唯一工号、唯一账号、初始密码、职位名称、权限角色和入职日期。在“全部人员”视图也可点击“新员工入职”。初始密码可手动填写或点击生成按钮，须为 12 至 128 位且包含字母和数字。
   职位名称和权限角色均可点击旁边的加号新增，保存后各部门可复用。新角色的权限默认不勾选，由组织管理员明确授权；职位或角色名称本身不授予权限。
3. 系统带出组织负责人作为直属领导，也可选择具备团队负责人权限的其他员工。董事长等无上级人员可勾选“无直属领导”，请假审批人另行指定；未指定审批人时可以完成入职，但不能提交请假。
4. 根据实际政策填写初始假期额度，年假默认 0 小时，不能把演示额度直接视作法定应享额度。
5. 完成入职后，将“账号已分配”窗口中的账号及初始密码私下交付给员工。员工首次登录必须改密，之后工作台显示组织、直属领导和请假审批人；请假转人工时进入该审批人的待办。普通汇报关系默认由直属领导审批，也可单独指定其他审批人。
6. HR 可编辑资料办理调岗、变更领导或停用账号。员工档案和组织编辑窗口可查看变更记录。

账号与员工是一对一关系，员工通过 `departmentId` 关联组织，通过 `managerId` 关联直属领导。组织负责人和员工直属领导分别维护，变更负责人不会自动覆盖员工已确认的汇报关系。

已有数据库启动时自动迁移：保留原用户 ID、部门、上下级、余额及请假记录；部门文本转为组织记录并补充账号和工号（旧账号均沿用原 ID），历史入职日期保留为空。默认顶级组织名为 FlowMind，HR 可改为实际公司名称。

详细数据关系、权限与边界见 [员工入职与组织流程](docs/employee-organization.md)。身份来自后端登录会话，`x-user-id` 不再用于认证，也没有匿名默认员工。普通员工不能自行注册、创建账号或分配角色。

## 登录与账号分配

首次启用时，在 `apps/api` 目录执行一次本机初始化命令：

```powershell
.venv/Scripts/python.exe -m oa.manage bootstrap-admin --username admin
```

命令创建独立的系统管理员账号，归属公司顶级组织，明确无直属领导，并生成一次性显示的随机初始密码。已有员工、HR 账号密码和审批数据保持不变；升级旧版已开通 HR 的数据库时也可执行一次。系统存在管理员后禁止重复初始化，用户名冲突不会覆盖旧账号。没有固定默认密码或公开管理员注册接口。

1. 系统管理员登录并修改初始密码，在“组织与人员 → 分配 HR 账号”填写 HR 资料、所属部门和初始密码。已有 HR 可通过档案开通登录或重置密码。
2. HR 登录改密后，通过入职表单为普通员工同步分配账号；旧员工通过“员工档案 → 开通登录账号”设置初始密码。
3. 普通员工忘记密码由 HR 重置；HR 或管理员账号由系统管理员管理。HR 不能修改其他 HR、管理员及具备组织管理权限的自定义角色账号，也不能通过新建角色或变更员工角色授予这些权限。本人可修改个人资料和密码，但不能停用自己或移除自己的管理权限。
4. 每位员工可通过顶部钥匙按钮修改自己的密码，或通过侧栏退出登录。停用账号、变更角色、重置密码、员工修改密码都会撤销旧会话；重新启用不会恢复旧会话。

密码使用带随机盐的 scrypt 哈希保存，凭据和会话分别存于 `auth_credentials`、`auth_sessions`，审计中不记录密码。会话使用 HttpOnly、SameSite=Lax Cookie，有效期 8 小时，服务重启不清除有效会话；写接口校验 CSRF，登录有频率限制。账号默认不开放自助注册或邮件找回。部署 HTTPS 时设置 `AUTH_COOKIE_SECURE=true`，并将 `WEB_ORIGIN` 配置为实际前端来源（多个来源逗号分隔）。建议前端和 API 使用同源反向代理。

## 架构

```text
React Web (apps/web)
        │ REST API + HttpOnly 会话 Cookie + CSRF
        ▼
Python FastAPI (apps/api/oa)
        ├── LeaveService：权限与业务事务
        ├── Leave State Machine：确定性状态迁移
        ├── Python Deep Agents：意图理解、OA 工具调用和智能审核
        └── SQLite：申请、余额、待办与审计
```

需要企业统一身份时可接入 SSO/OIDC；扩大部署时可将 SQLite Repository 替换为 PostgreSQL Repository。Agent 通过当前登录会话调用 OA API，不直接修改数据库。

## 运行

后端要求 Python 3.11 或更高版本；前端及 npm 开发脚本要求 Node.js 22 或更高版本。后端为 FastAPI + Uvicorn，原 Node.js/Fastify 后端已移除。

Windows PowerShell，在项目根目录执行：

```powershell
python -m venv apps/api/.venv
apps/api/.venv/Scripts/python.exe -m pip install -r apps/api/requirements-dev.txt
npm install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run dev
```

macOS / Linux 使用 `python3 -m venv apps/api/.venv` 和 `apps/api/.venv/bin/python -m pip install -r apps/api/requirements-dev.txt`，其余 npm 命令相同。已有 `.env` 不需要覆盖。

打开 <http://localhost:3000>。API 默认运行在 <http://localhost:9000>，交互式接口文档为 <http://localhost:9000/docs>，OpenAPI JSON 为 <http://localhost:9000/openapi.json>。

也可完全独立启动 Python 后端：进入 `apps/api`，执行 `.venv/Scripts/python.exe -m oa --reload`（Linux 使用 `.venv/bin/python`）。部署时安装 `requirements.txt`，执行 `python -m oa --host 0.0.0.0`，不使用 `--reload`。`scripts/api.mjs` 仅用于 npm 调起 Python，不包含后端业务逻辑。

根目录 `.env` 自动加载，`DATABASE_PATH` 的相对路径固定基于 `apps/api`，默认继续使用 `apps/api/data/smart-oa.db`。旧库自动兼容迁移，无需导出重建；迁移前应使用 SQLite 备份接口制作副本，不能在运行时只复制主 `.db` 而忽略 WAL。Python 依赖的已验证版本记录在 `apps/api/requirements-lock.txt`，需要复现本次环境时可安装该文件。

对话历史和操作回执保存在 SQLite 中，按用户隔离，空闲 30 天后不可继续使用。刷新页面或服务重启可恢复当前对话；聊天保留最近 40–60 条消息，业务审计独立保存。待确认预览 30 分钟有效，相关业务数据发生变化时需重新生成。当前仍须使用单 API worker：会话处理锁在进程内，多 worker 前需增加跨进程锁和执行任务协调。过期会话未自动物理清除，保留策略须按企业要求配置。

不配置模型密钥时，应用使用本地解析和规则检查，支持常用请假指令；复杂管理事项可使用聊天内“办理业务”表单。配置模型后启用 LangChain Deep Agents 理解更灵活的自然语言。模型只能查询和准备预览，不能执行确认。系统兼容实现 OpenAI Chat Completions 规范的官方、第三方或企业内部模型网关：

```env
OPENAI_API_KEY=your-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-5-mini
AGENT_TIMEOUT_MS=45000
```

使用第三方或企业内部兼容网关时，替换 Base URL 和模型名即可：

```env
OPENAI_API_KEY=your-compatible-api-key
OPENAI_BASE_URL=https://your-model-gateway.example.com/v1
OPENAI_MODEL=your-model-name
```

如果网关要求租户等额外请求头，可以配置：

```env
OPENAI_DEFAULT_HEADERS_JSON={"X-Tenant-Id":"your-tenant"}
```

为兼容只实现 `/v1/chat/completions` 的服务，模型客户端不会强制使用 Responses API。API Key 只保存在后端环境变量中，不会返回前端。

配置模型后，新的对话入口使用 `query_oa`、`apply_leave`、`prepare_oa_action` 和 `get_leave_policy` 工具。专用 `apply_leave` 工具先生成待确认预览，用户确认一次后完成请假创建与提交；只有明确要求暂存时才单独保存草稿。准备好的操作保存在服务端，用户核对卡片后，确认接口复用页面的业务服务完成权限、版本、余额、冲突和状态校验。模型没有确认工具，无法自行批准。模型调用默认 45 秒超时。旧版草稿接口保留兼容，Web 已切换至新的对话入口。

审批人可在申请详情或对话卡片中人工确认批准、驳回、退回补充与交接，两种入口共用权限和审计。审核模型异常或超时后转人工继续处理，服务重启也会恢复中断的审核任务。

## 演示路径

1. HR 为“陈默”和审批人“林夏”开通账号后，以“陈默”的账号登录工作台。
2. 打开“智能助手”，输入未来工作日的日期、假别和原因，例如：`2026-10-12请病假，原因：需要就医检查`。仅日期默认全天 09:00-18:00，扣除午休为 7.5 小时；示例日期需替换为实际未来工作日。
3. 核对预览中的假别、日期、原因和审批人，可先点击“修改信息”更正，随后点击“确认请假并提交”，一次确认即可送审。如果需要先上传材料，可在最初的需求中明确“先存草稿”，保存并上传材料后再说“提交这条”并确认。
4. 病假需人工核验，申请进入“林夏”的人工待办。
5. 退出后使用“林夏”的账号登录，在智能助手中说“待我审批”，选中申请，说“批准这条”并核对确认；也可通过“我的审批”页面处理。
   可在对话中说“查看详情”，核对 AI 建议、风险提示与材料。
6. 审批后切换到“已处理”，可查看审批意见、处理时间和完整流转记录；驳回后即使员工删除申请，审批人的历史仍保留。
7. 员工从已批准的申请发起部分销假；审批人批准后，在“假期台账”核对返还流水。

## 当前安全边界

- 所有状态转换由 `assert_transition` 校验；
- 审核 Agent 只能建议 `approve`、`need_information` 或 `escalate`；
- 新对话 Agent 只能查询、准备预览，执行确认仅接受当前登录用户的操作；
- 人工批准必须通过余额和冲突校验，AI 建议不能绕过这些规则；
- 使用乐观锁避免重复审批；
- 每次状态变化写入 `approval_actions`；批准、审批步骤和余额扣减在同一事务中完成，模型等待不占用事务。

当前按单服务、单工作进程、固定白班日历设计，支持带权限的部门试点。节假日由 HR 手动维护，通知为站内通知；尚未接入企业微信/钉钉、SSO、附件病毒扫描、考勤薪资与多级审批。上线试点前需使用真实组织、审批人、额度及公司日历完成配置与验收，并演练数据库备份恢复。详细边界见 [试点说明](docs/leave-pilot.md)。
